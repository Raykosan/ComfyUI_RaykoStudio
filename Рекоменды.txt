## Анализ корректности расчетов параметров

После проверки кода выявлены следующие проблемы:

### 1. **Black & White** (функция `apply_black_and_white`)
❌ **Ошибка**: параметры `yellow`, `cyan`, `magenta` не используются.  
Формула использует только коэффициенты для красного, зелёного и синего каналов:
```python
gray = r*(red/100) + g*(green/100) + b*(blue/100)
```
Это игнорирует цветовые тона жёлтого, циана и пурпурного, что не соответствует фотошопу.

**Правильный подход** (как в Photoshop):  
Для каждого пикселя определяется его доминирующий цветовой тон, и веса для преобразования в градации серого интерполируются между соседними цветами. Например, можно использовать HSV и взвешенную сумму яркостей по формуле:
```
gray = R * w_R + G * w_G + B * w_B
```
где веса зависят от оттенка:
- для красных тонов → `w_R = red/100`, `w_G = 0`, `w_B = 0` (но с плавным переходом)
- для жёлтых → комбинация `red` и `green`
- для зелёных → `green`
- для цианов → `green` и `blue`
- для синих → `blue`
- для пурпурных → `red` и `blue`

Реализация через интерполяцию по оттенку (hue):
```python
hue = cv2.cvtColor(img_rgb, cv2.COLOR_RGB2HSV)[:,:,0]  # 0..179
# задаём веса для каждого цвета в градусах (0=красный, 30=жёлтый, 60=зелёный, 90=циан, 120=синий, 150=пурпурный)
color_weights = {
    0: (red/100, 0, 0),
    30: (red/100, green/100, 0),
    60: (0, green/100, 0),
    90: (0, green/100, blue/100),
    120: (0, 0, blue/100),
    150: (red/100, 0, blue/100)
}
# для каждого пикселя интерполируем веса по hue
```

### 2. **Selective Color** (функция `apply_selective_color`)
⚠️ **Неточность**: маска для выбранного цвета является **бинарной** (по жёстким порогам HSV), тогда как в фотошопе коррекция применяется плавно, пропорционально близости пикселя к целевому цвету.

**Улучшение**: использовать не бинарную маску, а весовой коэффициент от 0 до 1, вычисляемый на основе расстояния в цветовом пространстве (например, в HSV).  
Пример для красного:
```python
hue_dist = np.minimum(np.abs(h - 0), np.abs(h - 180))  # красный около 0 или 180
mask = np.exp(-hue_dist**2 / sigma**2) * (s > 30)  # гауссово взвешивание
```
Аналогично для других цветов.

Формула преобразования CMYK в RGB **верна**:
- `K = 1 - max(R,G,B)`
- `C = (1 - R - K) / (1 - K + eps)`
- `M = (1 - G - K) / (1 - K + eps)`
- `Y = (1 - B - K) / (1 - K + eps)`
- После добавления поправок обратный переход:
  - `R = 1 - C - K`
  - `G = 1 - M - K`
  - `B = 1 - Y - K`

### 3. **Levels** (`apply_levels`)
✅ **Формула верна**:
```
normalized = (img - in_min) / (in_max - in_min)
result = clamp(normalized^(1/gamma), 0, 1) * 255
```

---

### 4. **Exposure** (`apply_exposure`)
✅ **Формула верна** (экспозиция в стопах):
```
multiplier = 2^(exposure/100)
result = img * multiplier + offset/100
```

---

### 5. **Color Balance** (`apply_color_balance`)
✅ **Маски и формулы коррекции** соответствуют распространённому подходу:
- Яркость вычисляется по стандартной формуле `0.299*R + 0.587*G + 0.114*B`.
- Маски теней, средних тонов и светов строятся через кусочно-линейные функции.
- Коррекция добавляется к соответствующим каналам (R,G,B) с учётом знака (положительное → Red/Green/Blue, отрицательное → Cyan/Magenta/Yellow).

---

### 6. **Channel Mixer** (`apply_channel_mixer`)
✅ **Формула полностью корректна**:
```
new_R = R * (red_red/100) + G * (red_green/100) + B * (red_blue/100)
new_G = R * (green_red/100) + G * (green_green/100) + B * (green_blue/100)
new_B = R * (blue_red/100) + G * (blue_green/100) + B * (blue_blue/100)
```
с последующим клиппированием в [0,1].
